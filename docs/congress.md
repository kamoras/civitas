# Congress, the president and agencies

Moved from the README. AGENTS.md states the rules; this page keeps the longer description and the measurements behind them.

## Congress record (half-hourly)

What each chamber did each day, for the Congress reports. Every half hour (`congress_activity.py`):

```
  ROLL CALLS ── senate.gov vote XML, clerk.house.gov/evs: from the highest
       │        stored number up, every member's position kept
  FLOOR LOGS ── House Clerk FloorSummary/YYYYMMDD.xml, Senate floor activity
       │        XML: today's and yesterday's, the live view of a session day
  DAILY DIGEST ─ the Congressional Record's own summary of each day (GovInfo,
                published the next day): replaces the live row as final;
                the last week until final, older days back-filled from the
                119th Congress's first day, 20 per run
```

**Newest first.** A run reads today's floor logs and the last week's Digests before any back-fill, and the current session's roll calls before the previous session's, so a fresh database (a first deploy, a data reset) shows this week within one run rather than after the Congress's first months.

**Nothing is rewritten.** Each passed, failed or reported measure, confirmation and committee meeting keeps the Digest's own sentence; the parser only decides which heading it sits under and reads the bill number. **Committee meetings and reports are findable without the date.** `/congress/committees` (a tab beside Reports and Bills) searches every Digest committee entry and report this Congress by committee, by words (all of them, anywhere in the entry or the committee's name) or by a bill number ("S. 465" or "S.465" is read as that bill, matched anywhere in the entry, since a markup names every measure it orders reported), newest first, as a plain GET form the server renders (`GET /api/congress/committees`, `/api/congress/committee-record`, `services/committee_record.py`, `daily_digest.bill_ids`). A bill's page lists the meetings and reports that name it ("In committee"), and a search on site search's Documents filter offers the matching committee entries beside its results, since they are not documents in its index. A bill's page also lists its floor debate ("Floor debate"): the Explore floor speeches whose Congressional Record heading prints the bill's number, grouped by day, chamber and heading with each speaker linked to their speech, and a speech's document page links the bill its heading names (`bill_record.floor_debate`, `speech_bills`, `daily_digest.heading_bill_ids`, the same grammar read in either case, since the Record's headings print "S.J. RES. 188"). The edge is the stated number only, never the speech's words or an embedding, and the bill's Congress is the speech day's; on the 2026-10-15 production copy 730 of 7,998 speeches name one of 160 bills. The rows are read with plain SQL filters per request (about four thousand a Congress), so no nightly step or index is added and nothing in `pipeline/` that the analysis fingerprint hashes changes. The Digest names a meeting's committee but not a report's, so reports are found by words and bill, not by committee. It is tested against real issues from both chambers (`backend/tests/fixtures/daily_digest`).

**The committee record in boxes (2026-10).** `/congress/committees` printed each meeting's Daily Digest paragraph whole (up to 283 words). Each meeting or report is now a box: chamber, kind and day over the committee (or the report's number), the Digest's first sentence quoted and credited with its pages (`lede` on each entry of `GET /api/congress/committee-record`, `app/sentences.lede`), the day and up to three bills as links in the credit, the committee's meetings on record as its figure (from `GET /api/congress/committees`), and the whole entry with every bill it names behind "More". The Digest names no meeting type as a field, so the title is the committee, never a type read from the prose. Measured on an iPhone SE (375 px) with the density audit's method on a local `next build` against the same database snapshot, main against this change: the longest block went from 283 words to 40, the first figure from none to 2.95 screens down, the first screen's prose from 21% to 14%, and the first entry stayed at 782 px; the page is 11.9 screens (11.7 before), the figures' column taking a little width from each quote.

**Served as reports.** `GET /api/congress/latest`, `/day/{YYYY-MM-DD}`, `/week/{any day of it}` and `/month/{YYYY-MM}` return each chamber's day or period: every count, the "passed both chambers" list, the closest votes (measured from each vote's own threshold, so cloture failing 59-41 is one vote short, not an 18-vote margin) and the one-line summary are computed in `congress_service.py` from the stored rows by rule, so a summary reads "The Senate passed 3 bills, agreed to 4 resolutions and took 3 record votes" and never characterises what passed. `GET /api/congress/votes/{chamber}/{congress}/{session}/{number}` is one roll call with every member's position, linked to their page. `GET /api/bills/{id}/record` is any bill's record (not only one a current member sponsored): Congress.gov's CRS summary, sponsors, cosponsors, actions and text versions, plus every stored roll call on it with each party's split. A Congress.gov part that could not be fetched is named in `unavailable` and never cached, so an outage does not read as a bill with no actions; the parts go out together, after the bill itself (all five at once for a bill a sitting member sponsored, which can't be a wrong id), on a limiter of their own rather than the pipeline's 1.2 requests a second, which held a cold page to five requests in a row and 3.6–5.8 seconds before its first byte (measured 2026-10-14; the hourly budget below is what bounds a reader's calls); the route waits at most 10 seconds, and a part still unfetched then is served the same way and fetched on a later visit. So is a part the hourly upstream budget can't pay for: the record is served with what is stored (a tracked bill's title and latest action from its own row when the bill part itself is missing), never a 503 that takes the page down, and a self-declared crawler (a `NameBot/1.0` token, `crawler`, `spider` or a `+https://` link in its User-Agent) spends a 50-call share of the hour rather than the readers' 150. Measured on 2026-10-11: crawlers naming themselves made 2,378 of 2,667 bill-page requests in a day (SemrushBot 1,858), and 2,479 of 2,740 bill records were the budget's 503.

**Nominations.** Every presidential nomination of the current Congress, from Congress.gov's nomination API (`pipeline/fetch/nominations.py`): one row per citation (`PN999-1`; Congress.gov splits a message naming several people into numbered parts) with the description, organization and position title, every nominee's name and state as published, every action, the referral committee's system code and the hearings Congress.gov lists, all in its own words. The status (pending, confirmed, returned, withdrawn) is its action vocabulary read into four words (`STATUS_CODES`: S05310, S05330, S05335; any other code is pending), a translation, not a judgement. A daily job at 14:50 UTC, outside the nightly chain and skipped while any chain pipeline runs, lists what changed since its cursor and reads each new or changed nomination oldest update first, at most 300 a run at half a request a second on top of the shared Congress.gov limiter (the pipeline process's 1.2 a second plus the public routes' 200 an hour keep the key under its 5,000), so the first backfill of a Congress (2,285 citations in the 119th) takes about eight days. Each nomination is committed as it is read and never across a request; the cursor moves only past what was applied in order, so an outage or one unreadable record is read again, never skipped. A roll call links its nominations by the citations its question states ("On the Nomination PN999-1", or seventy at once for an en bloc vote), read as tokens on request (`services/nomination_links.py`): on the 2026-10-15 production copy, 458 of the 119th Congress's 1,591 roll calls name a nomination, and all 1,339 citations they state match a listed nomination (before this, none linked anywhere). A confirmed federal judgeship links the Federal Judicial Center's biography when its directory (`judges.csv`, the file the justice pipeline reads) has exactly one judge with the same court, nomination date and surname; FJC states no PN, so those three exact fields are the whole key (measured on the 119th: every one of the 56 confirmed judgeships in courts the directory covers; the other 13 are D.C. local and territorial courts it does not). `/congress/nominations` shows the counts by status, the days from receipt to confirmation as a histogram per kind (civilian, judges, military; `GET /api/nominations/stats`, every figure computed by the backend) and the searchable list (`GET /api/nominations?status=&kind=&agency=&q=`); `/congress/nominations/{congress}/{PN}` (`GET /api/nominations/{congress}/{PN}`) shows one nomination with its actions, hearings, every roll call that names it and each senator's vote on the one to confirm, filterable by state. A roll call's page and a member's vote list name the nomination each vote decided and link it, labelled by the vote's own question ("Vote to confirm", "Vote to end debate (cloture)", "Vote to take up the nomination"; `nomination_links.VOTE_LABELS`), with the nomination's status shown only on the vote to confirm, and an en bloc vote counted by the citations its question names, however many are stored yet. Until the first backfill has read everything Congress.gov listed (`backfillComplete` in the sync's marker, sent as `backfill` by `/api/nominations/stats`), the page says how many of about how many are read and how many more days the rest should take, and holds the confirmation-time medians, since the nominations read first are the oldest updates. An organization links its agency page (`/agencies/{slug}`) when it is exactly one of the names that agency goes by in the registry: the Federal Register's name or short name, or the USAspending name the registry's crosswalk already matched to it, compared as `agencies.normalized_name` (`nomination_service.agency_index`; a name two agencies share links neither). On the 119th Congress's listing, 63 of 83 civilian organizations link, covering 776 of 938 civilian nominations; the rest (the Judiciary, the Foreign Service, international banks, some boards) and the military branches are shown as Congress.gov's text.

**Agency pages in boxes (2026-10).** An agency page no longer opens on the Federal Register's description (80 to 123 words at a reading grade of 19). It leads with "At a glance" in boxes: the budget figure (USAspending.gov, its obligations, outlays and every year behind "More"), the comment periods open as a figure with the proposed and final rule counts as its line, and the description quoted by its first sentence and credited to the Register, the whole of it behind "More" (`descriptionLede` on `GET /api/agencies/{slug}`, `app/sentences.lede`: the first sentence, or its first 40 words and an ellipsis, never a paraphrase). Measured on an iPhone SE (375 px) with the density audit's method on a local `next build` against the same database snapshot, main against this change: the Census Bureau's page went from 7.1 screens to 6.0, its longest block from 123 words to 46, the first screen's prose from 42% to 6%, its first figure from 1.21 screens down to 0.72, and its open comment periods moved up from 968 px to 836; the EPA's from 1,272 px to 909, and the Office of Administration's from 906 to 902.

**A bill goes by its short title.** A member's sponsored-legislation listing gives each bill the title it was introduced under, so a bill given its short title in committee kept the official one: H.R. 1 of the 119th Congress read "An act to provide for reconciliation pursuant to title II of H. Con. Res. 14." in the bill list, on its page and in search, and "big beautiful bill" found nothing. Congress.gov's titles list for each bill names its short and popular titles, and the site shows one when the listing title isn't already among them (`fetch/bill_display_titles.display_title`): the short title as enacted, else the newest whole-bill short title, else the popular title, word for word, never one naming a portion of the bill ("FEHB Protection Act of 2025" inside H.R. 1), and never the expansion of an acronym the listing already shows ("TAKE IT DOWN Act" stays). The bill page leads with it, says its title type as Congress.gov names it ("Short Title(s) as Passed House · Congress.gov") and puts the official title from the same list under it; the bills list shows the official title under it too, a member's vote list and party breaks name the vote's bill by it (the chamber's own title stays on hover and on the roll call's page), the roll call page names it beside the bill number, and both searches match it. Day, week and month reports keep each chamber's own wording, as everything in them does. A short title is usually given at introduction, when the listing already shows it, so the titles lists fetched are those of bills reported out of committee or further whose cached copy is missing or went stale as the bill moved (the hourly bill pass, after the statuses, at most 150 a pass; `scheduler._bill_refresh_pass`). It is read on the read path from the cache only, and lives under `fetch/` and in `scheduler.py`, so the analysis-code fingerprint does not move (checked: the same hash before and after).

**What an amendment vote was about (2026-10).** A vote on an amendment is titled by its sponsor and number ("Smith Amdt. No. 6805") and asks about the bill by number ("... to S. 4668 (No short title on file)"), so 202 of the 119th Congress's 1,591 roll calls said nothing a reader could use. The record says what each amendment would do, and `fetch/amendment_purpose.py` stores it word for word (`roll_calls.amendment`, `amendment_purpose`, migration 0058): for the Senate the roll call's own XML (`<amendment_number>`, `<amendment_purpose>`), for the House Congress.gov's house-vote record, which numbers the amendment the Clerk names only by its author, and that amendment's record (`purpose`). It runs after each half-hourly sync, 60 roll calls at a time, newest first; a read that fails (a timeout, a 5xx) leaves the row unread (an outage is never "no purpose stated"), and three in a row stop that chamber's reads for the run while the other chamber's go on; a record that isn't there (Congress.gov publishes a House vote's house-vote record a day or so late; a file that 404s) is skipped and asked again after a day, then twice as long each time up to a month (`amendment_misses`, `amendment_checked_at`), so neither a busy House day nor a dead file holds back older votes; and a record that states none is shown as "No statement of purpose on file". The roll call page quotes it as the official purpose with its source, and every vote list, the bill page's votes and the homepage's closest vote carry it. The roll call page draws the chamber as a seat chart, one dot per member grouped by party and marked by how they voted (shape as well as colour), with the party table under it as its text equivalent, inside the vote's share image. It lives under `fetch/` and in `scheduler.py`, outside the analysis-code fingerprint.

**How a bill got where it is (2026-10).** Half of the 119th Congress's laws (60 of 123) passed with no roll call, by unanimous consent or a voice vote, and their pages said "No recorded votes", which a reader takes for nobody voting. The bill page now reads its path from the official actions (`services/bill_journey.py`): Congress.gov lists many actions twice, once from the chamber and once from the Library of Congress ("Signed by President." under two codes; "Passed/agreed to in House: ..." restating the House's sentence), and same-day twins are folded into the chamber's wording with every code and roll call kept (S. 240's 27 actions are 20). Each folded action carries a one-line plain meaning from a checked-in glossary keyed by its action code (`app/data/bill_action_glossary.json`; a code is listed only where every action carrying it in the cached record shares one meaning). How each chamber passed the bill is read from its passage codes and the chamber's fixed formula ("by Unanimous Consent", "by voice vote", "by the Yeas and Nays"; a roll call wherever the action records one) and said plainly: "Passed the Senate by unanimous consent on December 11, 2025; no roll call is taken for that." A journey map above the stage ladder dates each stop the bill's type passes (introduced, committee, each chamber's floor, resolving differences, the President, law) with the time between them; the list is its own text equivalent. The votes section says how the bill passed instead of "No recorded votes" when no roll call was taken. Under the title a line lists the page's sections (Summary, Its path, Votes with their count, History, In committee, Text, Data & citation), and a CRS summary over 200 words shows its title line and first paragraph with the rest behind a native "Read the full CRS summary (N words)" disclosure (`SummaryBody`), which find-in-page still opens: H.R. 1's whole summary put its votes 55.6 screens down at 1280 px. The votes come straight after the bill's header, before the sponsor box, the summary and the "this week" strip (now after the record): on a phone they sat after all three, 3,665px down H.R. 1 at 390px with the summary folded, and 2,325px now. The latest five are listed and the rest sit behind "All N votes" (open when a `#vote-...` link names a folded one), and the chosen vote's party split and members open under its own row (`VotePanel`): below a 47-row list, tapping H.R. 1's third vote opened its split 8,272px further down a phone screen.

**Member pages at a glance (2026-10).** A senator's or representative's page now leads with a compact header (the ballot status as one line above the name, the committees folded to one line with the chips, office and sources behind it) and "Where <name> stands": the four peer strips as a small multiple, side by side on a desktop, each with its word, figure and one sentence, its method behind "How this is measured", and "Stands out" only when a measure is genuinely unusual. Section chips lead to the record behind it (money, votes, bills, votes with the president, approval at home) and what is also on record (holdings as a stacked bar, trades, positions, donor and vote links, the government record), each a box whose title, line and figure are the backend's (`boxes`), with everything else behind its "More". Votes with the president are shown once (the line in the votes column and the section lower down are gone), and the peer tables kept for screen readers no longer put every peer's link in the Tab order while hidden. Measured on a production build against a 2026-10-17 copy of the data, iPhone SE (375 × 667) and 1280 px, before and after: one senator 15.6 to 9.4 phone screens (first strip 2.23 to 0.85 screens down) and 7.1 to 3.9 desktop screens, a second 14.6 to 9.4 (2.45 to 0.91), and a representative with a long name and a ballot line 14.8 to 9.5 (2.71 to 0.99), the footer included. On a phone the ballot line and the breadcrumb take one line each (cut with an ellipsis; the full ballot lines are behind the committee line), the page's purpose drops the name the title already gives, and the choice of peers sits under the strips; every word of the old page's text, all disclosures open, is still on the new one apart from reworded labels.

**Member profile boxes, the backend (2026-10).** A senator's or representative's profile now carries every box line its redesign needs, written by the backend (`services/member_boxes.py`, `boxes` on `GET /api/politicians/{id}`): the committee count and the posts held ("N committees · Ranking Member, <committee>") with each committee's short name, a one-line ballot status (on the ballot, the seat on the ballot without the member as a nominee, or the year a senator's seat is next up), and each record box's kicker, headline, figure and line, counted from the same score breakdown, holdings, trade and survey reads the page already shows: the money in contributions under the election it is from, party-line votes against the party, how far the member's bills got ("N of M passed the Senate"), votes on the president's stated side with its verdict ("about as expected") and a subjectless `finding`, the share of the member's own party at home who approve ("N% of <state> Democrats approve"), the holdings total as disclosed ("$X+ disclosed across N assets", now also `totalShown` on the holdings response), trades, policy areas on the party line and the documents on record. The funding window's election is now kept (`funding_election_year`, migration 0071) and served as `funding.electionYear`; rows scored before say "most recent completed election" until the next run. The peers route says which measure stands out (`standsOutKey`, null when none does), so the page can show that line only when one does. Three data faults fixed beside it: the profile's approval figures and the score breakdown's disagreed in the last place (0.1148 against 0.115, which reads 11% and 12%), and both now serve the survey's own four places; a vote's `measureTitle` (the bill's short title, else its stored title, never an amendment's sponsor-only title) is served with every roll call a member's votes list, the flank breaks included; and trade asset names are put on one line at ingest and every stored one re-cleaned each night before re-filed trades are collapsed (measured on a 2026-10-17 copy: 4,138 of 4,916 House rows and 259 of 1,312 Senate rows carried newlines or runs of spaces).

**Each fact once on a member's page (2026-10).** The record boxes stated "Where <name> stands"'s figures a second time in another framing: the Votes box led with the strip's "16 of 499 party-line votes against the party" and drew the rate against the seat's again (3.2% against a 1.1% seat norm, the same figures: 16 / 499 is 3.2%), the Money box's line was the small-gift share against what is typical, and the Bills box's headline and line counted the bills by stage beside a strip counting them past committee. The comparison now lives only in the strips, and the boxes carry the record behind it (`services/member_boxes.py`): the Votes box says what the breaks were votes on (nominations, amendments, bills and resolutions, other questions, from each roll call's own fields; "14 breaks were on nominations", then the rest and the newest break's date, and no count when every break is one kind, since that count is the strip's), the Money box's line names the largest donor (an employer as its employees, the member's own committee left out), and the Bills box names the bill furthest along with its title and latest action ("S. 71 passed the Senate", or the newest bill when none is past referral). The seat-norm scale and the shares restated behind "More" are gone. The strip's tick is a rate while its figure was a count, so the breaks sentence now gives the rate too ("16 of 499 party-line votes (3.2%)").

**Bill pages in boxes (2026-10).** A bill page now leads with boxes in ruled columns, the homepage front page's vocabulary as one shared pair (`BoxGrid`, `RecordBox`, with `RecordFigure` drawing the same stat, split, dots and countdown figures the front page draws): where the bill is (a law's number and the days from introduction to law, or how long it has been in committee), what it does in the CRS summary's first sentence, quoted and credited, how far this Congress's bills get (the stage ladder), one box per chamber decision with the roll call's yea-nay split and each party's line, the votes, the history, the committee record, the cost estimates, the sponsor, the text and the floor debate. Each box's line is a template the backend fills from the stored record (`services/bill_boxes.py`, served as `boxes` on the bill record; the Digest's count as `headline` on `committee_record.search`), counted from the same lists the page shows, and everything the line doesn't say (every action, every Digest entry word for word, the whole summary, every cosponsor) sits behind the box's "More", a native disclosure find-in-page still opens; every recorded vote follows the boxes as before. Measured on an iPhone SE (375 px) against production on 2026-10-21: H.R. 1 went from 31.7 screens with no figure to 11.8 with its first figure 1.1 screens down, its longest block from 377 words (a Daily Digest entry) to 82 (the sources section, unchanged), its prose from 2,305 words to 375, and its reading grade from 8.6 to 5.7; a law with no roll call (S. 222) from 16.1 screens to 9.0, and a bill in committee (S. 1870) from 10.8 to 7.3, with a 650-word Digest entry moved behind "More". At 200% text on a 320 px screen the vote panel's party splits and state picker no longer push the page sideways.

**Checked against the sources (2026-10-11).** All 915 Senate roll calls of the 119th Congress match senate.gov's vote menus (number, date, tally), 45 sampled House roll calls match the Clerk's XML, every one of the 122 public laws is listed under the week Congress.gov dates it, and a sampled Senate day's 36 passed measures match its Digest entry for entry. Three things that did not hold are fixed. A House vote on an amendment is titled by the amendment the Clerk names ("Doe of Ohio Part B Amendment No. 1"); the Clerk gives it no description, and 90 read only as their bill's number (`congress_activity._vote_title`; stored votes are re-read once by `repair_house_requirements`). A Senate pro forma session timed to the second reads "for under a minute", not "for 0 minutes" (59 day reports). A bill the second chamber has passed is "Passed Both Chambers" (`BillStage.PASSED_BOTH`), not "In Other Chamber" until it reaches the President (52 bills and resolutions); it counts as Legislative Effectiveness's "passed the chamber" stage, as before. The sitemap lists every current-Congress bill a report links to, not only those a sitting member sponsors (36 were missing).

**An empty day says something (2026-10).** A default view that is all zeros tells a reader nothing, so each of these says what the site does know instead, from stored rows only. `/congress` on a day neither chamber did business (a pro forma sitting, a two-minute House session) led with "met for 2 minutes" above eight zeros; `GET /api/congress/latest` now carries `recess` (`congress_service.recess`) when the latest day had no floor action — no record vote, nothing passed, failed or confirmed; a committee report filed in a pro forma sitting is not floor action, and the House files them through a recess — and neither chamber is still on its live floor log — and the page leads with "Congress is out", the last day of business, each chamber's next sitting as the record gives it (marked when the program says pro forma), and opens the week of that last business with a link to the latest sitting. The bills page's "Active now" list is bills named by a live Action Center issue, which is most days none; when it is, `GET /api/bills?sort=hot` serves bills that moved this week (a recorded action in the last seven days, past referral) with `shown: "moved"` and `movedSince`, and the page says which list it is showing. The "bills in motion" headline is the backend's `inMotion`, no longer summed in the browser. A tracked bill's page states the base rate for its stage (`stageBaseRate`, `bill_service.stage_base_rate`): of this Congress's bills from sitting members, the share at that stage and the share that became law, and of those that got at least that far, the share that became law so far — a description of bills at the stage, worded so it never forecasts the bill (GovTrack's prognosis is the same idea); none for an earlier Congress's bill or one already law or vetoed. Above it the page leads with what the bill does, in the Congressional Research Service's own words (its summary's first paragraph, attributed and dated), and how far it has got: one row per milestone (introduced, reported by a committee, passed one chamber, passed both, became law) with the share of this Congress's bills that reached it and this bill's row marked (`stageMilestones`, `bill_service.stage_milestones`, over the same bills as the base rate; `StageLadder.tsx`). Its sources, the roll calls as JSON from the public API, and an APA-style reference close the page (`BillSources.tsx`, linked as "Data & citation" in the page's own menu). `/congress` leads with two pictures of the Congress so far, both shareable and each with its table (`GET /api/congress/glance`, `services/congress_glance.py`, `CongressGlance.tsx`): a calendar with a row a month and a cell a day, each cell split into the Senate and the House, lit when the chamber sat (its Record day in session, or a roll call that day) and brighter the more record votes it took; and the bill pipeline, how many of this Congress's bills from sitting members were introduced, reported by a committee, passed one chamber, passed both and became law, drawn on a log scale (19,195 introduced against 122 laws on the 2026-10-16 copy leaves every bar after the first invisible on a linear one). Each step is a link to the bills it counts: `GET /api/bills?reached=<stage>` (one of the milestones' stage codes, `bill_service.MILESTONE_HEADINGS`; anything else is a 422) keeps this Congress's bills from sitting members that got at least that far, through the same population and rule as the counts (`_this_congress`, `_reached`), so a vetoed bill is in "passed both chambers" and the list's total is the row's number. The bills page reads `?reached=` once, at mount, and lists them under the milestone's heading; the chamber, party and search filters narrow it with the heading saying so, and picking a stage in the funnel (a bill's current stage, `?stage=`) drops it rather than showing the overlap under either name. With a state picked in the header, "Your members this Congress" follows: each sitting member's roll calls voted and missed, latest three votes (with or against party, `member_positions`) and latest three bills, linking to the profile, from `GET /api/congress/members?state=` (the state in that one URL and nowhere else; `roll_call_positions.member_id` is indexed for it, 4.5 s to 1.6 s for California's 54 members). In a recess the week's lists fold behind their headings and counts, and the section cards' week and month tiles show the last day of business instead of "None". At 375 px the recess page went from 11.8 screens with no visual to 5.0 screens with the calendar at 1.0 screens, in the server-rendered HTML. The Action Center's Ongoing tab also lists monitors closed in the last 60 days, with when each was tracked and closed (`recentlyClosed` on `GET /api/action/monitors`; a closed monitor's row is last written when it closes, so `updated_at` is its closing day).

**Every box says where its figures are from (2026-10).** A sources audit of the live site found about 420 figures on `/congress` whose source was only in the share image's metadata. Each box now prints its source under it with the shared `SourceLine` (`components/shared/Type.tsx`): the calendar and its monthly table and the bill funnel (`CongressGlance.tsx`, with the date they run through), the day's and the week's or month's figures and the recess box (`RECORD_SOURCE` and `BILL_STATUS_SOURCE` in `lib/congress.ts`), the "this week" strip, each section hub card with a live figure (`sectionSource` in `lib/sectionPreviews.ts`; the seat map's and new House maps' cards link to those pages' own sources), the homepage's ballot and Congress boxes (Election Day by law, 2 U.S.C. 7, as `ELECTION_DAY_LAW` in `lib/elections.ts`), and each Senate and House contest's money on a state ballot (FEC filings, behind the box's "More"). A state's lean is called Civitas's own computation with Cook's formula wherever it is shown, never Cook PVI, which only a House district's pinned figure is.

**Figure-led intros (2026-10).** Three Congress pages opened with 30 to 53 words of intro, a third of a phone's first screen. Each now leads with one record box (`BoxGrid` / `RecordBox`) whose figure is the page's own figure and whose line is one sentence, with the intro behind its "More". `/congress` in a recess: the last week of business as the title (linked) and its sentence as the line, with the days since the last record vote or measure passed as the figure (`recess.figure`, counted by `congress_service.recess` on the Eastern date) and when each chamber next sits behind "More". `/congress/nominations`: "The president nominates; the Senate confirms." over the number of nominations read and the people they name. `/congress/president/{chamber}`: how many members voted with the president's stated position more often than similar seats as the figure, the rest in its line (`counts` on `GET /api/presidential-support/{chamber}`, counted by the backend; public API v1's shape is unchanged). Measured on an iPhone SE (375 px) with the density audit's method, main against this change on a production build: the first figure moved from 1.26 to 0.65 screens on `/congress` (first-screen prose 41% to 10%), from 1.16 to 0.79 on nominations (39% to 22%), and from 1.23 to 0.68 on the House's votes with the president, where the seat chart moved up from 1.23 to 1.01 (32% to 6%). The Congress calendar starts at 1.00 screens instead of 1.09, and the nominations' at-a-glance at 0.69 instead of 0.90.

**The pages.** `/congress` is the latest day either chamber met; `/congress/2026-09-24`, `/congress/week/2026-09-21` and `/congress/month/2026-09` are a day, a week and a month, each with the Senate and the House side by side. `/congress/bills` is the in-motion list that used to be `/bills` (old links redirect), and `/congress/bills/{id}` is any bill's page — of the current Congress, or of Congress N with `?congress=N` (a bill number names a different bill in each Congress, so every link that knows its Congress passes it, and the canonical keeps `?congress=` only for an earlier one): the CRS summary, sponsor and cosponsors, the full action history with a link to each day's report, text versions, and every recorded vote with each party's split and each member's position: the names wait behind a state pick or a "Show all N members' votes" button (`VoteMembers` `collapsible`), each group's count still shown, since S. 2403's page listed all 433 House members inline, 16 screens and 519 tab stops before its history (87 after); the roll call's own page lists them all. Every roll call also has a page of its own, `/congress/votes/{chamber}/{congress}/{session}/{number}`, on a bill or not: the question and what the vote was on (a nominee, or a bill linked to its page), the result as the chamber recorded it, the tally, each party's split, every member's position linked to their profile (filterable by state), the chamber's own record of it (Senate.gov or the House Clerk, the URL the fetch read it from) and an APA-style reference. Half of the 119th Congress's Senate roll calls (458 of 915 on 2026-10-14) are on nominations, which have no bill page, so until then a cabinet confirmation linked nowhere. Every place that lists a roll call links to its page (the day, week and month reports, the "this week" strip, the homepage's front page, a member's votes and party breaks, compare, an issue's "their record on it", the president's-position lists and a bill's vote panel), and the sitemap lists each one (`rollCalls` on `GET /api/sitemap`). An address with no roll call recorded is a real 404 (noindex) whose page points to the day reports and the bills list (its `not-found.tsx`); an outage is the Congress error page, never a 404. A House roll call prints only the Clerk's surname form ("Joyce (PA)"), so each member the site has a page for is served with their own name and district (`bill_record.vote_detail`: `name`, `district`), and a state's members are listed in district order, so a reader who knows their district finds their member at once. Past the first eight cosponsors, the rest sit behind a native "All N cosponsors" disclosure: a ninety-cosponsor bill put ninety links between a keyboard reader and the votes. The bills list's search box finds a bill by its number in any spelling ("S. 2398" as the hub prints it, "HR 997": that bill, not H.R. 9977; the number alone matches as a prefix, dots and spaces dropped, the member vote search's rule, `bill_record.typed_bill_number`) as well as by the words of its title or sponsor: each word typed, in any order, as the start of a word after the Porter stemmer has reduced both to their stems, so "flag burning" finds the "Flag Burners Act" and "student loans" a "Student Loan" bill (`services/word_search.py`, SQLite FTS5's own `porter` tokenizer over an in-memory index of the cached list, built once per snapshot; until 2026-10 the query had to appear in a title unbroken, and over 226 real titles two of their words found the bill 0.4% of the time, now 100%); by a short title it gained after it was introduced (below); typing a search leaves the "Active now" list for every bill, and a search opens every stage its matches sit at (it opened a stage only when all of them sat at one, which word matching made rare: "student loans" finds 34 bills at five stages), and every bill route reads an id the same way (`bill_record.canonical_bill_id`: `/api/bills/H.R.%20997/record` is HR.997's record). A bill number typed into the homepage's request slip ("H.R. 7008", "s 4668") opens that bill's page, and searched in site search a bill number goes straight to the bill's page. Every bill the site mentions links there rather than to Congress.gov: the votes and breaks on a member's profile, the bills a donor-vote link names (`billPageHref`; a recent House roll call is stored under a synthetic id, `HouseRC-2026-314`, and is served as its roll call's bill, else the vote's title, never the id), and an Action Center issue's related bills, each with the Congress it recorded (an entry that recorded none links only when the site holds the bill, to the newest Congress it holds it from). A day whose Digest is not out yet shows the chambers' live floor logs and says so. The House writes its log through the day; the Senate posts its log only after the session ends, so until then a Senate that has voted shows "Record votes so far" and says when its log comes, rather than an empty log. `/congress` renders per request, never at build time (the build has no backend, so a prerendered page was always the empty state until a reader's visit revalidated it). A report the backend could not serve reads "could not be reached" (`app/congress/error.tsx`), never "nothing recorded" or a 404; only the backend's own 404 means no day has been recorded. A day, week or month exists only for dates on record, from the first day either chamber is on record as meeting to today (`congress_service.record_span`); any other well-formed date is a 404 with `noindex`, titled "Congress day not found" (week, month), and a week or month links its neighbours only when they are on record. A 404's title comes from a layout in its own segment, since a route's `notFound()` discards its page's metadata: the day, week, month, with-the-president and Explore document routes each have one beside the roll call's and the bill's, and an address no route answers is "Page not found" (`app/not-found.tsx`); until 2026-10-15 those seven read only the site's name. Every date from 1789 to the next year used to answer a page of placeholders, and the week and month pages linked their neighbours without end: in October 2026 a crawler walked dates into 2027 from rotating addresses, and each address counted as a new visitor (about 1,900 a day against a usual 150 to 400). A second crawler in the same month walked the bill pages from about 2,700 addresses an hour with browser-like headers, and was counted as roughly 7,000 of 7,357 visitors on 2026-10-08; a page now counts only once the same client's browser has also made one of the requests the running page makes (Next's link prefetches), which that crawler never did (`frontend/src/proxy.ts`). The page's own beacon that replaced the header check for a day was refused by the EasyPrivacy list most blockers enable (`/track-visit?`), so readers with a blocker went uncounted; the requests counted now are ones the site needs in order to work, and nothing is sent to evade a blocker. A third crawler, from 2026-10-23, ran the pages in full Chrome from rotating cloud addresses, so its own link prefetches confirmed it (about 760 of 790 confirmed visitors on 2026-10-24, none of which reported a page load); links and forms now prefetch only on a page in view in a browser no automation drives (`navigator.webdriver`, `frontend/src/components/Link.tsx`), and the admin Traffic tab marks a day with more confirmed visitors than reported loads, since stored visits can't be corrected afterwards.

**A file is not a session.** On a day the Senate does not meet it still publishes its floor file, holding only when it reconvenes; the sync reads that as not in session (it first read as "The Senate met" for Friday and Saturday, 2026-09-25/26), and re-reads every not-yet-final day of the last week so a wrong row corrects itself.

**No Record, said plainly.** GPO publishes the Congressional Record for every day either chamber is in session. A past day with no Record (behind the back-fill cursor, which stops before any day it could not read, or found absent at least three days on) reads "No Congressional Record was published for this day" rather than "no record yet", and the week and month strips say "No Record". It states the fact and not "neither chamber met": GPO very rarely prints two small consecutive days as one issue.

**A missing file is not a failed fetch.** A 404, or senate.gov's redirect of a missing file to its "not found" page, means the chamber has nothing for that day. Anything else writes nothing, so a day is never made final from part of its Digest, and the back-fill stops before a failed day to retry it.

## Votes with the president

How often each member votes with the president's stated position, beside what members of the same party in seats that lean the same way do. Informational: not in `SCORE_WEIGHTS`, and no score reads it. It runs as the Supplementary pipeline's last step (`analyze/presidential_support.py`), and is shown on every member's profile and at `/congress/president/house` and `/senate`.

```
  OMB INDEX ──── whitehouse.gov's list of Statements of Administration Policy
       │         (SAPs, OMB Circular A-19): only PDFs not yet read are fetched
  READ ───────── each PDF's date, the chamber it is addressed to ("(House)",
       │         "(Senate)"), the measures its title block cites, an amendment
       │         number it names, its opening and closing paragraphs
       │         (fetch/omb_statements.py)
  POSITION ───── support / oppose / no position on passage, by embedding
       │         similarity to written prototypes (analyze/sap_position.py);
       │         the sentence it was read from is stored and shown
  MATCH ──────── each stored roll call (Congress Record, above) to the statement
       │         that applies to it
  TALLY + FIT ── per member: votes on the president's side / counted votes;
                 per chamber and party: the expected rate by seat lean
```

**The source.** The president's position comes only from a signed, citable statement tied to the measure. OMB lists every SAP of the administration on one page; the index and the PDFs are served without a bot wall (the site's WordPress JSON API answers 403 and is not used) and `robots.txt` allows both. On 2026-10-13 it listed 194 statements for the 119th Congress: 125 addressed to the House, 69 to the Senate. One covers nineteen resolutions without citing any by number and cannot be matched to a vote.

**Whose positions.** "The president" is the sitting one (the presidents table's `is_current`, from the roster). A Congress that spans an inauguration counts only statements issued and roll calls cast since the sitting president's term began (`presidential_support.presidency_start`), so an outgoing administration's position never counts as its successor's.

**Which votes count.** A roll call counts when it is the chamber's final vote on a measure (passage, adoption, concurrence, a veto override), read from the chamber's own question wording, or a vote on an amendment a statement names by number; a statement addressed to that chamber covers the measure, issued on or before the vote; no later statement on the measure (in either chamber) has superseded it; and the statement supports or opposes passage. Procedural votes (cloture, motions to proceed, discharge, table, recommit) are left out because no statement addresses them. A Yea advances the measure, so the president's side is Yea under a supporting statement and Nay under an opposing one; present and not voting are not votes. On the 2026-10-13 record that is 122 House and 27 Senate roll calls. Many Senate statements were never followed by a final vote: the Senate disposed of most war-powers and disapproval resolutions on motions to discharge or proceed, which are not counted.

**Reading the position.** The statement's opening paragraph states the position on passage and the closing paragraph the recommendation to the President; a provision-by-provision statement (an appropriations bill, the NDAA) opens by thanking the committee and takes no position, and its votes are not counted. The candidate sentence most similar to a support or oppose prototype decides, unless it is nearer the "other" prototypes, with no tuned threshold. Checked against a hand reading of all 193 readable statements: 185 agree (95.9%); the eight that don't are seven positions read as "no position" and one statement recommending signature "with amendments" read as support. No support was read as oppose or the reverse.

**The expectation.** Per chamber and party, a fractional-response logit (Papke & Wooldridge 1996) of members' rates on their seat's party-signed lean (the Cook PVI measure Constituent Alignment uses), each member weighted by their counted votes and bent at a swing seat only where the bend predicts the party's members better out of sample (`score_calculator.select_opposed_kink`, as for Constituent Alignment's expectation; since 2026-10, when the 119th House's Democrats had a bend fitted on seven members that held-out fit did not support), fitted on this Congress's members every night (AGENTS.md §3a) and written to `/data/presidential_support_reference.json`. A member's expected rate is their party's fit at their seat's lean. No shrinkage is applied to either rate.

**Uncertainty.** Each rate carries its 95% Wilson score interval (Wilson 1927; Agresti & Coull 1998), which keeps a real width at 0% and 100%, where most members sit. A member is "more" or "less" often than expected only when that interval misses the expected rate; the expected rate's own uncertainty is not included. With 27 Senate votes the intervals are wide, and the page says how many votes each rate rests on.

**Bounded.** Every OMB request has a 30-second timeout and two retries; a run spends at most 15 minutes reading new statements (the first run reads all of them, later runs one or two), leaves the rest for the next night, and the step as a whole is cut off at 25 minutes. Like every Supplementary phase it is best-effort: a failure is recorded and alerted, and the phases before it are not affected. The embedding model loads only when there is a new statement to read, and classification and the rebuild run off the event loop.

**Served.** `GET /api/presidential-support/{chamber}` and `/member/{id}` (the site), `GET /api/public/v1/presidential-support/{chamber}` (the public API, with a contract test). Every number is computed by the backend; the wording is neutral by construction (voting with or against the president is neither good nor bad).

## Agencies

`/agencies` and `/agencies/{slug}` make federal agencies records of their own (`api/agencies.py`). An agency is the Federal Register's: its `/api/v1/agencies.json` lists 473 (abolished ones included), each with a slug, a description, a parent and sub-agencies, stored in `agencies`. Each agency page shows what it spends, the documents it issued and the executive orders that name it, every block with its source and the day it was read. `/agencies` is the directory; `/executive/budgets` (the Executive section's Budgets tab, its own page since 2026-10, when it was an anchor on the directory and both tabs opened one page; outside `/agencies` so no agency's slug can be shadowed by it, and its first address, `/agencies/budget`, redirects permanently while no agency holds that slug) charts every agency's budgetary resources for the year, largest first, each bar linked to its agency where the names matched. A static segment under `/agencies` shadows an agency slug of the same name, so the agency sync alerts if the Register ever lists one (`fetch/agencies.RESERVED_SLUGS`, held equal to the static pages by `test_agencies.py`).

- **Spending** comes from USAspending.gov: the toptier list (`/api/v2/references/toptier_agencies/`, one request) for the current fiscal year's budgetary resources, obligations and outlays, and `/api/v2/agency/{code}/budgetary_resources/` for the same by fiscal year (one request per agency, about 110). USAspending names no Federal Register agency, so the two lists are joined by name (`fetch/agencies.crosswalk`): token-sorted names ("Agriculture Department" and "Department of Agriculture" sort alike) compared by SequenceMatcher ratio, one USAspending agency to at most one Register agency, at a threshold derived by `scripts/calibrate_agency_crosswalk.py` and stored in `app/data/agency_crosswalk.json`. Its labels come from evidence the score never reads: where an agency's USAspending abbreviation equals exactly one Register agency's short name, that pair is a positive, and the same agency's best score against every other Register agency a negative; the threshold maximizes Youden's J over them (0.834 on 2026-10-15: 76 of 80 positives and 1 of 80 negatives at or above it). 94 of 111 toptier agencies matched; the other 17 are stored with no match and named on the page as not linked, never paired with a runner-up. A sub-agency's page points to its department's budget, which includes it. A fiscal year USAspending hasn't reported is never shown as $0: its toptier list answers 0.0 for an agency with no submission yet (on 2026-10-16 all 10 agencies listed at 0.0 for FY2026 had 0.0 obligations and outlays too, and no FY2026 entry in their year-by-year record, while 5 had a nonzero FY2025, the Railroad Retirement Board's $17.8B among them), so a year counts as reported only when the year-by-year record has it; otherwise the page says "not yet reported" and leads with the latest year that is, and the agency is left out of the year's total and shares. An agency USAspending's list stops including is kept with the date it dropped out (`agency_budgets.retired_at`), never read as zero. With no budget to show, the page says which case it is: not yet read (an outage), no USAspending agency matched by name, listed with no figures for any year, or dropped from the list. An agency page also lists the Action Center issues that cite one of its documents (the issue's own `related_explore_ids`).
- **Documents.** A Federal Register document's agency is the most specific one its `agencies[]` lists (the FAA, not the Transportation Department it sits under), stored with its slug in `explore_documents.agency_slug` at ingest, so a document reaches its agency with no name matching. Documents stored before the column are read for it by the nightly Federal Register refresh, 2,000 a night beyond the refresh's own 90-day window. A department's page lists its sub-agencies' documents too: open comment periods (rules first, as the Today tab orders them, with paperwork notices folded under "Paperwork notices (N)"), proposed and final rules (newest first), and a link to site search's Documents filter for the agency (`/search?tab=documents&agency={slug}`, read from `GET /api/explore?agency={slug}`; its agency select lists every agency with documents). A joint rule counts for its first listed issuer only.
- **Executive orders naming it**: every executive order lists the Executive Office of the President as its agency, so these are found by text, the keyword index's exact phrase for the agency's Register name or its USAspending name. When the keyword index can't be asked the section says so rather than reading as "none".
- **Lobbying aimed at an agency** is not shown. LDA filings list the government entities each activity lobbied, but the LDA API can't filter filings by entity, so a per-agency figure would mean downloading every filing of a year.

Both lists are read by a weekly job outside the nightly chain (`scheduler._agency_sync`, under the `AGENCY_SYNC` lease): tried when the pipeline process starts and hourly at :30, each source read once a week has passed since it last stored (or never has), so a source that failed is retried within the hour (one request while it is down) and a new deploy or a fresh database fills the agency pages as the pipeline comes up. Until the Register's list has been read once, `/agencies` says it hasn't been read rather than counting 0 agencies. The same job links documents stored before `explore_documents.agency_slug` existed to their agency (`agencies.link_documents`), hourly until none is left: a document whose stored agency has no sub-agencies is linked by that name (the Register's issuer can be no more specific), and a department's has its issuer read from the Register, newest first, 500 an hour (5,855 such documents in 2026-10, about twelve hours, where the nightly refresh's 2,000 a night took five nights). A number the Register has no document for is removed, as the nightly refresh does. Until every document is linked the API says how many are (`documentsLinking`, `documents.linking`) and the pages word every count as a count so far: an empty list reads "None linked to this agency yet", never "None". A data reset starts the sync as soon as it finishes. The directory's name search matches a short name exactly first ("EPA", "IRS", "FBI"), then a whole name, then every typed word as the start of a word of the name (`matchAgencies`): a substring match put the EPA sixth of 28, behind every "Department". Browsing, it lists departments and other agencies with sub-agencies, with the independent agencies and those with nothing on Civitas each behind a disclosure, two columns from a laptop up (9.8 screens and 121 tab stops at 375 px before, 4.7 and 55 after). A source that can't be read returns None, leaves what is stored as it was, and raises an ops alert; an empty list counts as unread.
