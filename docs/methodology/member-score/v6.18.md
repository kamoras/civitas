# Member score v6.18

## A vote is against the party only when the parties split on it

**Before (v6.17).** A vote counted with or against the member's party by how
the parties actually voted on its roll call. When no roll call had been
fetched for it (a key bill whose floor vote wasn't found), the bill's
*content* lean stood in: a Republican voting for a bill whose text read
Democratic counted as a break, however Republicans actually voted.

**Now.** A vote counts only through its roll call's party split
(`stamp_roll_call_outcome` records `partySplit`; `normalize_votes` reads
only that). A roll call is party-labeled when at least 65% of one party
voted Yea and at most 35% of the other did; a member breaks when they vote
with the other side. With no roll call there is no label, and the vote does
not count toward Constituent Alignment. The content lean still feeds the
per-area partisan depth breakdown, which is not a count of breaks.

**Measured before the change.** Every party label in a random 25
representatives' records (119 House roll calls) matched the Clerk's own
party totals, and all 45 Senate roll calls matched in 10 senators' records
against senate.gov. The fallback reached no label in either sample, so no
score in them moves; the change closes the path rather than repairing
published scores.

**Also.** Each stored vote now records its roll call (`key_votes.roll_call`,
Alembic 0009), and the vote API returns the Congress record's question,
date, result and each party's tally with it, so every break shows why it
is one. The profile's list of breaks read only "key" votes; a member whose
breaks were all recent roll calls (one House member had six) saw the count
and then an empty list. It now lists every break.
